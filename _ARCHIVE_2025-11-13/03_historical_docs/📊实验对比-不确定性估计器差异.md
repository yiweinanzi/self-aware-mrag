## 🎯 根本原因

### ImprovedUncertaintyEstimator (100样本，成功)

**实现方式**:
```python
class ImprovedUncertaintyEstimator:
    def __init__(self, config=None):
        # ✅ 不需要mllm_model
        self.clip_model = AutoModel.from_pretrained(clip_model_path)
        self.clip_processor = AutoProcessor.from_pretrained(clip_model_path)
        self.text_encoder = SentenceTransformer('all-MiniLM-L6-v2')
    
    def estimate_text_uncertainty(self, text):
        # ✅ 使用关键词匹配 + 长度启发式
        keywords = ['which', 'what', 'who', 'where', 'when', 'why', 'how']
        complexity = sum(1 for kw in keywords if kw in text.lower())
        return normalize(complexity + len(text.split()) / 50)
    
    def estimate_visual_uncertainty(self, image):
        # ✅ 使用CLIP特征统计
        features = self.clip_model.encode_image(image)
        return features.std().item()
    
    def estimate_alignment_uncertainty(self, text, image):
        # ✅ 使用CLIP相似度
        text_emb = self.clip_model.encode_text(text)
        image_emb = self.clip_model.encode_image(image)
        similarity = cosine_similarity(text_emb, image_emb)
        return 1 - similarity
```

**优点**:
- ✅ 不依赖MLLM，独立工作
- ✅ 计算快速（只需CLIP forward pass）
- ✅ 可以产生有区分度的不确定性值
- ✅ 实际效果好（EM 62%）

### CrossModalUncertaintyEstimator (1353样本，失败)

**实现方式**:
```python
class CrossModalUncertaintyEstimator:
    def __init__(self, mllm_model=None, config=None):
        self.mllm_model = mllm_model  # ⚠️ 传入了None！
    
    def estimate(self, text_query, image_query):
        if self.mllm_model is None:
            # ❌ 降级为简化版
            return self._estimate_simplified(text_query, image_query)
        
        # 理想情况：使用MLLM的hidden states计算
        # 但因为mllm_model=None，永远不会执行到这里
    
    def _estimate_simplified(self, text_query, image_query):
        # ❌ 超简化版本
        text_unc = 0.8 if len(text_query.split()) > 15 else 0.3
        visual_unc = 0.5  # 固定值
        alignment_unc = 0.0  # 固定值
        
        # 所有MRAG-Bench问题都>15词
        # → total = 0.4*0.8 + 0.3*0.5 + 0.3*0.0 = 0.47
        return {'total': 0.47}
```

**问题**:
- ❌ mllm_model=None导致降级为简化版
- ❌ 简化版逻辑过于粗糙
- ❌ 所有样本返回相同的0.47
- ❌ 完全失去区分度

## 💡 解决方案

### 方案A：修复CrossModalUncertaintyEstimator（理论更优）

**修改**: `flashrag/pipeline/self_aware_pipeline_qwen3vl.py`

```python
# Step 1: 先初始化generator
self.generator = self._init_generator()

# Step 2: 传入generator给uncertainty_estimator
self.uncertainty_estimator = CrossModalUncertaintyEstimator(
    mllm_model=self.generator,  # ✅ 传入真实模型
    config={...}
)
```

**优点**:
- 理论上更准确（使用MLLM hidden states）
- 符合论文描述（SeaKR的Gram矩阵方法）

**缺点**:
- 需要调整初始化顺序
- 计算开销更大
- 需要测试验证

## 📝 答案：每次实验的指标都是一样的吗？

**回答**: **不是**，但要看用的哪个estimator：

| 估计器 | 不确定性是否相同 | 指标是否稳定 |
|--------|----------------|------------|
| **ImprovedUncertaintyEstimator** | ❌ 不同（正常） | ✅ 稳定（62% EM） |
| **CrossModalUncertaintyEstimator** (mllm_model=None) | ✅ 完全相同（异常） | ❌ 下降（47% EM） |

**结论**:
- 100样本实验用ImprovedUncertaintyEstimator，每个样本的不确定性不同，性能正常
- 1353样本实验用CrossModalUncertaintyEstimator但配置错误，所有样本不确定性相同，性能下降

---

## 🎓 核心教训

1. **配置很关键**: `use_improved_estimator`这个开关直接决定了性能
2. **初始化顺序**: 依赖关系必须正确（generator必须先于uncertainty_estimator初始化）
3. **简化版的陷阱**: 降级逻辑可能导致隐蔽的性能问题
4. **监控很重要**: 应该实时监控不确定性分布，及早发现异常
