# 性能下降根因分析报告

**日期**: 2025-11-01  
**问题**: Self-Aware-MRAG在全数据集(1353样本)上性能严重下降

---

## 📊 性能对比

| 实验 | 样本数 | EM | F1 | VQA-Score |
|------|--------|-----|-----|-----------|
| **100样本实验** | 100 | **62.0%** | **67.8%** | 19.4% |
| **1353样本实验** | 1353 | **47.3%** | **54.0%** | 15.8% |
| **性能下降** | - | **-14.7%** | **-13.8%** | -3.6% |

---

## 🔍 根因分析

### 关键发现1：所有样本的不确定性完全相同

```bash
$ grep -o "uncertainty=0\.[0-9]*" full_dataset_CrossModal_experiment.log | sort | uniq -c
   1353 uncertainty=0.4700
```

**结论**: 全部1353个样本的不确定性都固定为0.4700，这明显不正常！

---

### 关键发现2：系统使用了简化版估计器

**代码路径**: `flashrag/modules/uncertainty_estimator.py`

**问题代码**:
```python
def estimate(self, text_query: str, image_query=None, return_details: bool = False):
    if self.mllm_model is None or not TORCH_AVAILABLE:
        # ⚠️ 进入简化版分支！
        return self._estimate_simplified(text_query, image_query)
```

**简化版逻辑**:
```python
def _estimate_simplified(self, text_query: str, image_query):
    # 文本不确定性：基于问题长度
    text_uncertainty = self._estimate_text_simplified(text_query)
    
    # 视觉不确定性：固定值！
    visual_uncertainty = 0.5 if image_query is not None else 0.0
    
    # 对齐不确定性：固定为0！
    alignment_uncertainty = 0.0
    
    # 总不确定性
    total = 0.4 * text_uncertainty + 0.3 * 0.5 + 0.3 * 0.0
```

**文本不确定性逻辑**:
```python
def _estimate_text_simplified(self, text: str):
    words = text.split()
    word_count = len(words)
    
    if word_count < 5:
        return 0.3  # 短问题
    elif word_count > 15:
        return 0.8  # 长问题 ← 所有MRAG-Bench的问题都>15词！
    else:
        return 0.3 + (word_count - 5) * 0.05
```

**计算验证**:
- text_uncertainty = 0.8 (所有问题>15词)
- visual_uncertainty = 0.5 (固定值)
- alignment_uncertainty = 0.0 (固定值)
- **total = 0.4 × 0.8 + 0.3 × 0.5 + 0.3 × 0.0 = 0.32 + 0.15 = 0.47** ✓

### 关键发现3：mllm_model=None导致降级

**初始化代码**: `flashrag/pipeline/self_aware_pipeline_qwen3vl.py:135-136`

```python
self.uncertainty_estimator = CrossModalUncertaintyEstimator(
    mllm_model=None,  # ⚠️ 致命问题：传入了None！
    config={...}
)
```

**为什么传入None**:
- 在pipeline初始化时，还没有加载generator（Qwen3-VL模型）
- 或者认为不需要mllm_model来计算不确定性（这是错误的理解）

---

## 🎯 影响分析

### 1. 不确定性估计失效

| 模态 | 应该的方法 | 实际使用的方法 | 效果 |
|------|-----------|---------------|------|
| **文本** | Gram矩阵 + eigen_score | 简单字数统计 | ❌ 完全失效 |
| **视觉** | Attention variance | 固定值0.5 | ❌ 无区分度 |
| **对齐** | JS divergence | 固定值0.0 | ❌ 无意义 |

### 2. 自适应检索失效

```python
if uncertainty > threshold:  # 0.47 > 0.35
    should_retrieve = True   # ← 所有样本都检索！
```

**结果**: 
- **期望**: 37.6%的样本不检索（基于真实不确定性）
- **实际**: 100%的样本都检索（因为0.47 > 0.35）
- **后果**: 退化为"Always Retrieve"模式，引入大量噪声

### 3. 模态选择失效

由于所有样本的三个不确定性分量都是固定值：
- text_uncertainty = 0.8
- visual_uncertainty = 0.5
- alignment_uncertainty = 0.0

**结果**: 所有样本都选择text模态检索（因为0.8最大）

---

## 💡 解决方案

### 方案A：传入真实的MLLM模型（推荐）

**修改位置**: `flashrag/pipeline/self_aware_pipeline_qwen3vl.py:135`

```python
# 修改前
self.uncertainty_estimator = CrossModalUncertaintyEstimator(
    mllm_model=None,  # ❌ 错误
    config={...}
)

# 修改后
self.uncertainty_estimator = CrossModalUncertaintyEstimator(
    mllm_model=self.generator,  # ✅ 传入Qwen3-VL模型
    config={...}
)
```

**但是有问题**：初始化顺序
- uncertainty_estimator在第123行初始化
- generator在第175行才初始化
- 解决：调整初始化顺序，先初始化generator

### 方案B：修改CrossModalUncertaintyEstimator使其独立工作

**修改逻辑**:
1. 文本不确定性：使用BERT/BGE embeddings计算语义熵（不需要MLLM）
2. 视觉不确定性：使用CLIP image features的熵（已有CLIP模型）
3. 对齐不确定性：使用CLIP的text-image相似度方差

**优点**: 
- 不依赖MLLM
- 计算速度更快
- 更模块化

**缺点**:
- 需要重写代码
- 可能不如MLLM的hidden states准确

## 🎓 经验教训

1. **初始化顺序很重要**: 依赖关系必须正确
2. **参数校验不足**: None值应该触发警告或错误
3. **缺少单元测试**: 应该有测试确保不确定性计算正常
4. **日志不够详细**: 应该记录不确定性的三个分量，而不只是total
